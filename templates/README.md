# __APP_NAME__

An Odin API generated by Dagda. `app/` is your source code; `vendor/dagda/` is a
locked framework snapshot. Commit both along with `dagda.json` and `dagda.lock`.
No generated file is rewritten by later builds.

## Requirements

Linux x86_64, the pinned Odin compiler recorded in `dagda.lock`, `cc`, and libpq
17 or newer. Put the Dagda CLI on PATH. Select your installed pinned compiler:

```sh
export DAGDA_ODIN=/absolute/path/to/odin
# Or install it under .tools/odin-dev-2026-11a/odin, or put it on PATH.
dagda doctor
dagda test
dagda build
```

The compiler release URL and checksum are in `dagda.lock`; install from the
verified archive. The CLI does not download or silently replace your compiler.
`dagda test` runs Odin request tests without a running database or an io_uring
loop. The executable needs permitted io_uring and PostgreSQL when serving.

## Run locally

The Compose credentials below are only for the local development database. The
port binds to loopback. Starting Compose is explicit; Dagda never starts Docker.
If port 55432 is occupied, change both Compose and your local environment.

```sh
docker compose up -d --wait
cp .env.example .env
set -a
. ./.env
set +a
dagda doctor --database
./build/__APP_NAME__ serve
```

The CLI/runtime do not automatically load `.env`. You can instead supply
`DAGDA_DATABASE_URL` for an existing local PostgreSQL instance. Current Dagda
accepts Unix sockets or numeric loopback hostaddr, not remote/DNS connections.
No migrations are needed for this starter's endpoints.

```sh
curl http://127.0.0.1:8080/
curl http://127.0.0.1:8080/health/ready
curl http://127.0.0.1:8080/echo -H 'Content-Type: application/json' \
  -d '{"message":"hello"}'
```

`GET /` identifies the app. `POST /echo` demonstrates typed JSON and field
validation. Health routes are provided by Dagda. Edit `app/routes.odin` and its
Odin tests to add behavior. Database operations require external integration
tests; the in-process request client rejects attempts to use a live database.

`dagda build --release` enables optimization and writes build metadata. This M1
CLI does not yet provide watch/restart, migrations, resource generation, packaging,
or automatic upgrades. Builds verify the locked vendor files; modify application
code in `app/`, not the framework snapshot. The checksums detect source drift,
not authenticity of arbitrary third-party lock files.
